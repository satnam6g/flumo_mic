Technical Wiki

A deep technical reference for developers, contributors, and curious users who want to understand exactly how Wireless Mic works under the hood.

System Architecture

Wireless Mic consists of two components that communicate over your local network using UDP:

Android (Sender)                              Windows (Receiver)
┌────────────────────┐                    ┌──────────────────────┐
│  Microphone        │                    │  UDP Socket          │
│  ↓                 │                    │  ↓                   │
│  AudioRecord       │   UDP/55555        │  Decrypt (AES-256)   │
│  (Kotlin native)   │ ──────────────►    │  ↓                   │
│  ↓                 │   Encrypted        │  PyAudio             │
│  AES-256 Encrypt   │   Packets          │  ↓                   │
│  ↓                 │                    │  VB-Audio Cable      │
│  Flutter UDP Send  │                    │  ↓                   │
└────────────────────┘                    │  Any Windows App     │
                                          └──────────────────────┘

The Android app uses Kotlin's AudioRecord API through a Flutter platform channel to capture raw PCM audio. Each audio chunk is encrypted with AES-256 CBC and sent as a UDP packet. The Windows client receives, decrypts, and plays the audio through PyAudio, routing it to VB-Audio Virtual Cable for use in any application.

Android App (Sender)

Technology Stack

  • Framework: Flutter (Dart) for the UI layer
  • Audio Capture: Kotlin native code using Android's AudioRecord API
  • Platform Bridge: Flutter EventChannel for streaming audio data from Kotlin to Dart
  • Encryption: AES-256 CBC implemented in Dart
  • Networking: Dart dart:io UDP socket

Audio Pipeline

  1. AudioRecord captures 48kHz, 16-bit PCM mono audio
  2. Audio data is streamed to Flutter via EventChannel
  3. Each chunk (~4800 bytes, ~100ms) is encrypted with AES-256 CBC
  4. Encrypted data (IV + ciphertext) is sent over UDP to the Windows client

Windows Client (Receiver)

Technology Stack

  • Language: Python 3.10+
  • Audio Playback: PyAudio (PortAudio bindings)
  • Decryption: PyCryptodome for AES-256 CBC
  • Virtual Audio: VB-Audio Virtual Cable driver

Audio Pipeline

  1. UDP socket listens on port 55555
  2. Incoming packets are split into IV (first 16 bytes) and ciphertext
  3. Ciphertext is decrypted using AES-256 CBC with the shared key
  4. PKCS7 padding is stripped
  5. Raw PCM audio is played through PyAudio to VB-Audio Virtual Cable

Client Interface

The Windows client runs as a desktop GUI (Tkinter) with a live level meter, audio controls, recording, and a system tray icon. While it's running you can use these global hotkeys:

  • Ctrl+Alt+M — Mute / unmute the stream
  • Ctrl+Alt+R — Start / stop WAV recording (saved to Music\WirelessMic)
  • Ctrl+Alt+S — Toggle live monitoring through your speakers/headphones

The client also logs events to wireless_mic.log for debugging.

Network Protocol

  • Protocol: UDP (chosen for low latency — no handshake, no retransmission overhead)
  • Port: 55555 (default)
  • Packet Structure (v2): [WM][ver][seq][timestamp][IV][AES-256-CBC ciphertext] — the sequence number and timestamp enable live packet-loss % and jitter stats
  • Audio Chunk: ~4800 bytes of raw PCM per packet
  • Bandwidth: ~768 kbps payload (48,000 Hz × 16 bit × 1 channel), plus encryption and header overhead

UDP is intentionally used instead of TCP because real-time audio streaming prioritizes low latency over reliability. A dropped packet results in a brief audio gap, which is far less disruptive than the stuttering caused by TCP's retransmission delays.

Encryption Implementation

For a complete breakdown of the encryption architecture, including key derivation, IV generation, and packet structure, see the dedicated Security page.

Key Points

  • PIN is never transmitted over the network
  • Key = SHA-256(PIN) computed independently on both devices
  • Each packet has a unique random 16-byte IV
  • PKCS7 padding ensures proper AES block alignment

Contributing

Wireless Mic is open-source and welcomes contributions. Here's how to get started:

  1. Fork the repository on GitHub
  2. Clone your fork locally
  3. Set up the development environment (Flutter SDK 3.10+ for Android, Python 3.10+ for Windows)
  4. Make your changes on a feature branch
  5. Submit a Pull Request with a clear description of your changes

For bug reports and feature requests, use GitHub Issues. For general discussion, join the GitHub Discussions.
