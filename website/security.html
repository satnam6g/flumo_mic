PIN-Protected Security

Every audio packet is individually encrypted with AES-256 before it ever leaves your phone. No cloud servers, no accounts — your voice stays between your devices.

AES-256 CBC Encryption

The same encryption standard used by governments and financial institutions worldwide. Every single audio packet is encrypted in real-time using AES-256 in CBC (Cipher Block Chaining) mode, ensuring that even if someone intercepts your network traffic, the audio data is completely unreadable without the correct key.

PIN-Based Key Derivation

The Windows client generates a random 4-digit PIN at startup. This PIN is run through SHA-256 to derive a 256-bit encryption key. You enter the same PIN on your Android device to establish a matching key. No PIN is ever transmitted over the network — both sides compute the key independently.

Random IV Per Packet

Each audio packet uses a unique, randomly generated 16-byte Initialization Vector (IV). This ensures that identical audio data produces different ciphertext every time, defeating pattern analysis attacks. The IV is prepended to each encrypted packet for decryption on the receiver side.

Local Network Only

Wireless Mic operates exclusively over your local Wi-Fi network or USB tethering connection. Audio data never leaves your local network, never touches the internet, and never passes through any third-party server. There are zero cloud dependencies.

Zero Data Collection

Wireless Mic collects absolutely no user data. There are no analytics, no telemetry, no crash reports, and no user accounts. The app doesn't even require internet permission. Your audio, your device, your privacy — fully under your control.

Open Source & Auditable

The entire codebase is publicly available on GitHub under the MIT license. Security researchers, developers, and users can inspect every line of code to verify that the encryption implementation is correct and that no data is being exfiltrated.

How the Encryption Works — Step by Step

  1. PIN Generation: When you launch the Windows client, it generates a random 4-digit PIN and displays it on screen.
  2. Key Derivation: Both the Windows client and Android app independently compute SHA-256(PIN) to derive a 256-bit AES encryption key.
  3. Audio Capture: The Android app captures raw PCM audio at 48kHz, 16-bit mono from your phone's microphone.
  4. Encryption: Each audio chunk (~4800 bytes) is encrypted using AES-256 CBC with a fresh random 16-byte IV. PKCS7 padding is applied to ensure proper block alignment.
  5. Transmission: The encrypted packet (IV + ciphertext) is sent over UDP to your PC on port 55555.
  6. Decryption: The Windows client extracts the IV, decrypts the ciphertext using the shared key, strips the padding, and plays the raw audio through VB-Audio Virtual Cable.

Encryption Specifications

Algorithm AES-256 CBC (Cipher Block Chaining)
Key Length 256 bits (32 bytes)
Key Derivation SHA-256 hash of 4-digit PIN
IV Length 128 bits (16 bytes), random per packet
Padding PKCS7
Transport UDP, port 55555, local network only
